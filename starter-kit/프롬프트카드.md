### P0 — 빠진 프로그램 클로드가 찾아서 깔기

**로그인 직후 맨 처음 붙여넣는 카드입니다.**
`node -v` `py -3 -V` `git --version` 중 **하나라도 안 나왔다면** 직접 다시 설치하지 마시고 이 카드를 쓰세요.

```
내 컴퓨터에 오늘 강의에 필요한 프로그램이 다 깔려 있는지 확인해줘.

확인할 것:
  Node.js  →  node -v        (v22 이상)
  Python   →  py -3 -V       (3.11 이상)
  Git      →  git --version  (버전 상관없음)

규칙:
- 세 개를 하나씩 실제로 실행해서 확인하고, 결과를 표로 보여줄 것
- 안 깔렸거나 버전이 낮은 게 있으면 웹 검색으로 지금 시점의 공식 다운로드 주소와
  최신 안정 버전을 찾을 것. 기억에 있는 주소를 그냥 쓰지 말고 반드시 검색해서 확인할 것
- 그다음 그 프로그램을 나 대신 설치해줘. winget 으로 되면 winget 으로,
  안 되면 설치 파일을 내려받아 실행하는 방법을 한 줄씩 알려줄 것
- Python 은 반드시 PATH 에 추가되도록 설치할 것 (Add python.exe to PATH)
- 설치가 끝나면 다시 확인해서 버전이 나오는지 눈으로 보여줄 것
- 이미 깔려 있는 것은 건드리지 말 것. 지우거나 덮어쓰지 말 것
- 설치 말고 다른 파일은 만들지 말 것
```

> ⚠️ **Claude Code 하나만은 예외입니다.** 이 카드는 클로드 안에 붙여넣는 것이라,
> 클로드가 없으면 붙여넣을 창 자체가 없습니다. **Claude Code는 사람이 먼저** 깔고
> (파워셸 `irm https://claude.ai/install.ps1 | iex`), 나머지(Node.js·Python·Git)를 이 카드로 맡기세요.
> 스타터킷의 `환경점검.bat` 을 먼저 더블클릭했다면 대부분 이미 깔려 있습니다.

> **설치 중에 두 가지가 뜹니다.**
> ① 클로드가 "이 명령을 실행할까요?" → `Enter` 로 허용. 물어보는 게 정상입니다.
> ② 윈도우가 "이 앱이 변경하도록 허용하시겠습니까?" → **이건 사람이 눌러야** 넘어갑니다.

> **설치 직후에는 창을 새로 열어야 인식됩니다.** 클로드가 "설치했는데 확인이 안 된다"고 하면
> 고장이 아닙니다. `/exit` → 창 닫고 새로 열기 → `claude` 다시 부르기 → 확인.
> 회사 노트북은 **설치 자체가 막혀** 있을 수 있습니다. 그때는 클로드도 못 깝니다.

### P1-B — 핵심 컬러 뽑기 (내 브랜드 색 확정)

```
workspace/memory/facts.md 의 "내 회사 겉모습" 색 네 줄을 내 브랜드 색으로 바꿔줘.

내 색의 근거 (둘 중 하나만 채운다):
  A. 로고·명함·홈페이지 캡처가 있다 → workspace/브랜드/ 폴더에 넣어뒀다. 파일 이름: [logo.png]

순서:
1. A면 그 이미지를 열어 가장 넓게 쓰인 색을 "기본 색"으로 뽑고, 같은 계열의 더 어두운 색을 "진한 색",
   대비되는 색 하나를 "강조색", 기본 색을 아주 옅게 만든 것을 "옅은 색"으로 정한다.
   B면 업종·느낌에 맞는 팔레트 3안을 표(이름 / 4색 hex / 한 줄 이유)로 보여주고 내가 고르게 한다.
   내가 고르기 전에는 파일을 바꾸지 않는다.
2. 정해진 4색으로 workspace/결과물/브랜드_컬러.html 을 만든다 — 색 견본 4칸 +
   그 색으로 칠한 제안서 표지 1장 + 표 머리 1줄 미리보기. 인터넷 주소는 쓰지 않는다.
3. 진한 색 위에 흰 글씨를 올렸을 때 대비가 4.5:1 미만이면 진한 색을 더 어둡게 고치고 그 사실을 말한다.
4. facts.md 의 네 줄(진한 색·기본 색·강조색·옅은 색)만 바꾸고 줄 끝에 "확정 (오늘 날짜)"라고 적는다.
   다른 줄은 건드리지 않는다.
5. 끝나면 네 색의 hex 와 브랜드_컬러.html 경로를 한 줄로 알려준다.

규칙:
- 색은 반드시 #RRGGBB 여섯 자리로 쓴다
- 이 4색이 오늘 만드는 제안서(P4)·교재(P8)·프로필(S7)에 그대로 쓰인다는 것을 알고 정한다
- 로고 파일이 없는데 있다고 하지 말 것. 없으면 B로 진행한다
```

> 🎨 **명함이나 홈페이지 색을 그대로 쓰는 게 제일 좋습니다.** 로고 파일은 `workspace/브랜드/` 폴더를 만들어 넣으세요.
> 끝나면 `workspace/결과물/브랜드_컬러.html` 을 브라우저로 열어 보고, 마음에 안 들면 "더 차분하게", "강조색만 주황으로" 처럼 말로 바꾸세요.

## 모듈 2 · 일하는 방법 가르치기

### P4 — 첫 스킬 만들기

```
지금 열려 있는 이 스타터킷 폴더 안의 .claude/skills/제안서/ 에 SKILL.md 를 만들어줘.
(홈 폴더의 .claude 가 아니라 스타터킷 안의 .claude 다.)
먼저 workspace/memory/facts.md 를 읽고, 거기 적힌 내 회사 이름·로고 글자·색 4개를
이 스킬 안에 그대로 박아 넣어줘.

[이 스킬이 하는 일]
교육 제안서를 만든다. 고객사에 그대로 보낼 수 있는 수준까지.
결과물을 두 개 만든다 — 내용 초안(.md)과 슬라이드 덱(.html).

[Step 0 — 착수 전 반드시 확인할 것]
아래 6가지를 한 번에 모아서 묻고, 답이 오면 되묻지 말고 끝까지 뽑는다.
  1. 고객사 이름과 업종
  2. 교육 대상 (직급·직무·인원)
  3. 교육 시간
  4. 예산 또는 시간당 단가
  5. 일자 확정 여부
  6. 이 교육을 왜 하려는지 (담당자가 풀려는 문제)

  → 1·2·3·6 중 하나라도 비면 제안서를 쓰지 말고 그것부터 묻는다.
     특히 6번이 없으면 어느 회사에나 붙는 표준 커리큘럼밖에 못 나온다.

[작성 원칙]
- 모듈은 4개 안팎. 각 모듈에 네 줄 —
  모듈명 / 학습 목표 / 주요 내용 / 학습자 활동(+몇 분)
  "제목 + 한 줄"로 끝내지 않는다.
- 시간 합계가 요청한 총 시간과 맞는지 검산하고, 맞는다고 문서에 적는다.
- 기대효과는 형용사가 아니라 담당자가 윗선에 보고할 수 있는 문장으로.
  ✕ "역량이 향상됩니다"
  ○ "교육 후 2주 내 각 팀이 적용 사례 1건씩을 제출합니다"
- 견적은 단가 × 시간 계산 과정을 표에 보이고, 부가세 별도 여부를 반드시 쓴다.

[절대 금지]
- 안 들은 금액·날짜·인원·실적을 지어내지 않는다. 모르면 '확인 필요'로 둔다.
- 실제로 하지 않은 교육을 실적으로 쓰지 않는다.

[문장 규칙 — 여기 적히는 모든 글에 적용]
- 제목은 [핵심 수단] + [정량 수치] 로 쓴다. 추상적 제목을 쓰지 않는다.
  ✕ "업무 효율성 향상 방안"   ○ "처리 시간을 40% 줄이는 보고 절차 재설계"
- 한 문장에 한 메시지만 담는다. 두 문장을 넘기지 않는다.
  "~하며, ~하고, ~함으로써" 로 길게 잇지 않고 끊어 쓴다.
- 서술형 문장은 마침표를 찍는다.
  개조식(- 로 시작하는 항목)은 끝에 마침표를 절대 찍지 않는다.
- 개조식은 명사만 나열하지 않는다. [주체] + [구체적 행동] + [결과] 를 한 줄에 담는다.
  ○ "- 담당자 사전 협의 1회로 업종 사례를 맞춰 당일 이해도 편차 축소"

[쓰지 않을 단어]
  대폭 · 획기적인 · 혁신적인 · 엄청난 · 극대화 · 다양한 · 효율적인 · 최적의
  → 근거 없는 형용사·부사를 빼고 사실과 숫자로 바꿔 쓴다.

[받은 자료를 줄일 때]
- 사용자가 준 자료의 수치·고유명사는 하나도 빼지 않는다.
  줄이는 것은 문장 길이지 데이터가 아니다.

[표를 만들 때]
- 세로 격자선을 넣지 않는다. 가로 구분선만 쓴다.
- 굵게와 강조색은 실제 수치·변화량에만 쓴다. 그게 표의 주인공이다.

[결과물 ① 내용 초안]  ← 경로는 스타터킷 루트 기준. 스킬 폴더 안에 workspace 를 만들지 말 것
workspace/결과물/<날짜>_<고객사>_제안서초안.md

[결과물 ② 슬라이드 덱]  ← 이게 고객사에 나가는 것
```

### P8 — 교재(워크북) 스킬 만들기

> 📌 **제안서 다음으로 많이 하는 일**이라 기본 카드에 넣었습니다.
> 제안서가 **팔기 위한 문서**라면, 교재는 **교육장에서 손에 쥐어주는 것**입니다.

```
.claude/skills/교재/ 폴더에 SKILL.md 를 만들어줘.
먼저 workspace/memory/facts.md 를 읽고 회사 이름·로고 글자·색 4개를 스킬 안에 박아 넣어줘.

[이 스킬이 하는 일]
학습자가 손에 쥐고 쓰는 워크북을 만든다. 진행 설계가 아니라 배포물이다.
결과물을 두 개 만든다 — 내용(.md)과 인쇄용 워크북(.html).

[Step 0 — 착수 전 확인할 것]
  1. 무엇을 근거로 만드나 — 확정된 교안 또는 제안서 (파일 경로)
  2. 어떤 형식 — 학습자용 워크북 / 강사용 교재 (기본: 학습자용 워크북)
  3. 인쇄 부수와 흑백/컬러
  4. 제출 마감일

  → 1번이 없으면 만들지 않는다. 근거 없이 만든 교재는 강의와 따로 논다.
     교안도 제안서도 없으면 "제안서부터 만드시겠어요?" 하고 되묻는다.
  → 4번은 받는 즉시 알려준다. 교재 마감은 강의일보다 먼저 온다.

[챕터마다 반드시 들어갈 여섯 블록]
  ◎ 학습 목표    — 이 챕터를 끝내면 뭘 할 수 있는가
  한 줄 정의     — 핵심 개념을 한 문장으로
  본문           — 설명. 예시는 학습자 업종에서 가져온다
  실습 / 워크시트 — 직접 써보는 칸
  ✓ CHECK       — 스스로 확인하는 질문 2~3개
  핵심 요약      — 3줄 이내

[작성 원칙]
- 워크북은 빈칸만 있으면 손이 안 간다. 맨 위 한 줄에 예시를 채워두고 나머지를 비운다.
- 실습지는 한 쪽에 하나만.
- 챕터는 교안(또는 제안서)의 모듈과 1:1로 맞춘다. 모듈이 4개면 챕터도 4개다.
- 흑백 인쇄를 전제로 색으로만 구분되는 표시를 쓰지 않는다.

[절대 금지]
- 근거 문서에 없는 내용을 교재에 넣지 않는다. 필요하면 근거부터 고친다.
- 출처 없는 통계·인용을 싣지 않는다.
- 강의 진행 방법(시간표·활동 운영)을 교재에 넣지 않는다. 그건 교안이다.

[문장 규칙 — 여기 적히는 모든 글에 적용]
- 제목은 [핵심 수단] + [정량 수치] 로 쓴다. 추상적 제목을 쓰지 않는다.
  ✕ "업무 효율성 향상 방안"   ○ "처리 시간을 40% 줄이는 보고 절차 재설계"
- 한 문장에 한 메시지만 담는다. 두 문장을 넘기지 않는다.
  "~하며, ~하고, ~함으로써" 로 길게 잇지 않고 끊어 쓴다.
- 서술형 문장은 마침표를 찍는다.
```

```
내가 자주 하는 업무 하나를 스킬로 만들려고 해. 업무 이름: [강의 후기 블로그]

다음 칸으로 넘어가.

  1. Step 0 정보 수집 — 이 일을 시작하기 전에 나는 뭘 알아야 하는가 (3~9개)
  2. 상황 분류 — 같은 일이라도 상황마다 톤·형식이 달라지는가? 갈래를 나눠줘

  4. 절대 금지 — 지어내면 안 되는 것, 하면 안 되는 것
  5. 출력 형식 — 결과물이 어떤 모양이어야 하는지, 파일은 몇 개 나와야 하는지
  6. 저장 위치 — workspace/결과물/ 아래 어떤 이름 규칙으로

[규칙]
```

### P17-1 — PPT·PDF 내용 추출 도구 (필요할 때만)

```

- 필요한 라이브러리가 없으면 먼저 설치해줘
```

### 네이버 블로그 연결 — 임시저장 + 이미지 자동생성

이제 블로그 스킬은 **원고(.md)까지** 만듭니다. 여기서 그 원고를 **실제 네이버 블로그
임시저장함**에 넣고, 이미지까지 채웁니다. **발행(공개)은 하지 않습니다** — 임시저장까지만
자동이고, 확인·발행은 항상 사람이 합니다. 도구는 `naver-blog/` 폴더에 이미 들어 있습니다.

이미지는 두 갈래 중 하나입니다.

| | Google Flow (무료) | Gemini API (유료) |
|---|---|---|
| 비용 | 구글 계정만 있으면 사실상 무료(일일 한도 있음) | 장당 몇 센트 |
| 방식 | 직원이 브라우저를 띄워 만들고 파일로 저장 | 완전 자동 — 임시저장 실행 시 알아서 생성·삽입 |
| 준비물 | `flow-image-JJ` 스킬 설치 + 구글 계정 최초 로그인 | `naver-blog/.env` 에 결제 등록된 `GOOGLE_API_KEY` |
| 오늘은 | ✅ **기본으로 이걸 씁니다** | 계정·결제가 이미 있으면 이쪽도 괜찮습니다 |

**flow-image-JJ 설치 (최초 1회)**


### P20-b — 슬랙 알림 창구 만들기 (모듈 4에서 만든 앱 재사용)
