# 전문 스킬 카드 5장 — 강사 업무용

> 제안서(**P4**)와 교재(**P8**)는 기본 카드로 옮겼습니다. 여기는 **블로그 · 교안 · 메일 · 프로필 · 카드뉴스** 다섯 장입니다.

모듈 2에서 카드 P4로 만든 **제안서 스킬**이 이 회사의 기준선입니다.
Step 0 · 작성 원칙 · 절대 금지 · 출력 형식 · 저장 위치가 다 들어 있고, 슬라이드 덱까지 나옵니다.

**여기 다섯 장은 나머지 업무를 그 수준으로 올리는 카드입니다** — 블로그 · 교안 · 메일 · 프로필 · 카드뉴스.

> 📌 **언제 쓰나**: 모듈 2를 통과한 뒤. 시간이 남으면 강의장에서, 아니면 집에서.
> 한 장에 5~10분씩 걸립니다. 다섯 장을 다 할 필요는 없어요. **내가 제일 자주 하는 일부터** 하세요.
>
> ⚠️ 각 카드에 **"같은 일을 하는 스킬이 이미 있으면 덮어쓸 것"** 이 들어 있습니다.
> 이걸 빼고 돌리면 같은 일을 하는 스킬이 두 개가 되어, 어느 쪽이 뜰지 알 수 없게 됩니다.

## 먼저 — 전문 스킬은 뭐가 다른가

아마추어 스킬과 전문 스킬의 차이는 분량이 아니라 **칸이 몇 개냐**입니다.

| 칸 | 하는 일 | 이게 없으면 |
|---|---|---|
| ① **Step 0 정보 수집** | 일 시작 전에 필요한 걸 **한 번에 모아서** 묻는다 | 반쯤 만들다가 "그건 안 알려주셨는데요"를 반복 |
| ② **상황 분류** | 같은 일도 상황마다 다르다. 갈래를 나눈다 | 영업 메일과 독촉 메일이 같은 톤으로 나감 |
| ③ **작성 원칙** | 이 바닥에서 통하는 기준 | 그럴듯하지만 현장에서 안 먹히는 결과물 |
| ④ **절대 금지** | 하면 안 되는 것을 명시 | 금액·날짜를 지어냄 |
| ⑤ **출력 형식** | 결과물이 어떤 모양이어야 하는지 | 매번 모양이 달라 손보는 데 더 걸림 |
| ⑥ **저장 위치** | 어디에 어떤 이름으로 | 결과물을 못 찾음 |

**①번이 제일 중요합니다.** 프로는 일을 시작하기 전에 묻습니다.

아래 다섯 장은 전부 이 여섯 칸을 채우도록 짜여 있습니다. (기본 카드 P4·P8 도 같은 여섯 칸입니다.)

## S2 — 블로그 스킬

```
.claude/skills/ 폴더에 '블로그' 스킬을 만들어줘.
아래 내용을 SKILL.md 에 그대로 담아줘.

[이 스킬이 하는 일]
강의 후기·현장 스케치를 블로그 글로 쓴다.

[독자가 누구인지 — 이게 이 스킬의 핵심]
이 글의 독자는 일반인이 아니라 **교육 담당자**다.
"재밌었다"를 읽으러 오는 게 아니라 **우리 회사도 이 교육을 할지 판단하러** 온다.
그래서 감상문이 아니라 판단 자료로 쓴다.

[Step 0 — 착수 전 확인할 것]
한 번에 모아서 묻는다. 아는 것만 알려줘도 된다고 안내한다.
  1. 고객사 (공개 가능한지도 함께)
  2. 업종
  3. 과정명
  4. 대상 (직급·직무·인원)
  5. 교육 시간
  6. ⭐ 이 교육만의 특별한 점 ← 가장 중요
  7. ⭐ 다룬 내용
  8. 교육 후 변화·반응
  9. 어떤 조직에 추천하고 싶은지

  → 6·7번이 없으면 글이 아니라 광고가 된다. 이 둘은 반드시 받는다.

[글 구조]
1. 인사 + 어떤 교육이었는지 두세 줄
2. 판단 카드 (표로) — 고객사 / 업종 / 대상 / 인원 / 시간 / 형태 / 난이도 / 진행일
3. 이 교육의 차별점 (박스로 강조)
4. 실제로 다룬 내용 — 모듈별로
5. 교육 후 변화 (구체적인 반응·수치가 있으면 그것으로)
6. 이런 조직에 추천합니다
7. 문의 안내

[작성 원칙]
- 문장은 짧게. 한 문단 3~4줄.
- 숫자가 있으면 숫자로 쓴다. "많은 분이" ✕ / "32명이" ○
- 사진 자리는 [사진: 무엇] 으로만 표시하고 이미지는 만들지 않는다.
- 마지막에 SEO 제목 후보 5개를 뽑고, 각각 왜 그 제목인지 한 줄씩 붙인다.
- 해시태그 15개 이내.

[절대 금지]
- 고객사 실명은 공개 가능 확인을 받기 전에는 쓰지 않는다. 확인 전이면 '○○기업'.
- 참가자 개인의 말을 실명과 함께 쓰지 않는다.
- 안 들은 만족도 점수·재의뢰율 같은 수치를 지어내지 않는다.
- 발행하지 않는다. 초안까지만 만들고 사람이 검토한다.

[저장]
workspace/결과물/<날짜>_<고객사>_블로그초안.md

[기존 스킬 처리 — 이 줄을 빼면 스킬이 두 개가 된다]
- 같은 일을 하는 스킬이 .claude/skills/ 에 이미 있으면 (이름이 비슷한 다른 스킬 포함)
  새로 만들지 말고 그 폴더의 SKILL.md 를 이 내용으로 통째로 덮어쓴다.
- 폴더 이름이 다르면 이 이름으로 폴더를 바꾸고, 옛 폴더는 지운다.
- 덮어쓴 뒤 .claude/agents/ 의 직원 파일에서 이 스킬을 가리키는 줄을 찾아
  새 이름과 맞는지 확인하고, 안 맞으면 고친다.
- 무엇을 지우고 무엇을 고쳤는지 마지막에 목록으로 알려준다.

[트리거]
"블로그", "후기 써줘", "현장 스케치", "포스팅"
```

**이러면 정상** — 글 + SEO 제목 5개 + 해시태그가 한 파일에 나옵니다.

## S3 — 교안 스킬

> ⚠️ **교안과 교재는 다른 일입니다.** 이걸 헷갈리면 스킬 두 개가 같은 걸 만듭니다.
>
> | | **교안** (S3) | **교재** (기본 카드 P8) |
> |---|---|---|
> | 답하는 질문 | 이 강의를 **어떻게 가르칠까** | 학습자 손에 **무엇을 쥐어줄까** |
> | 결과물 | 모듈 구조 · 분 단위 시간표 · 학습자 활동 · 강의 스크립트 | 인쇄용 교재 · 워크북 · 슬라이드 |
> | 순서 | **먼저** | 교안이 확정된 **다음** |

```
.claude/skills/ 폴더에 '교안' 스킬을 만들어줘.
아래 내용을 SKILL.md 에 그대로 담아줘.

[이 스킬이 하는 일]
강의를 어떻게 진행할지 설계한다. 인쇄물이 아니라 진행 설계다.

[Step 0 — 착수 전 확인할 것]
  1. 과정명
  2. 대상 (직급·직무·인원)
  3. 총 시간과 쉬는 시간 방식 (예: 4시간, 중간 10분 2회)
  4. 학습 목표 — 교육이 끝나면 학습자가 무엇을 할 수 있어야 하는가
  5. 사전 수준 (입문 / 기초 / 중급)
  6. 장소와 환경 (노트북 있는지, 조 편성 가능한지, 인터넷 되는지)

  → 4번이 없으면 설계를 시작하지 않는다. 목표 없이 짠 시간표는 못 쓴다.
  → 6번은 활동 설계를 좌우한다. 노트북이 없으면 실습을 못 넣는다.

[설계 원칙 — 성인 학습]
- 어른은 강의만 들으면 안 남는다. **경험 → 성찰 → 개념 → 적용** 순서로 배치한다.
  자기 경험을 꺼내게 한 다음 개념을 얹고, 마지막에 자기 일에 적용시킨다.
- 도입 5분이 하루를 좌우한다. 왜 이 교육을 듣는지부터 납득시킨다.
- 4시간이면 학습자 활동을 최소 2개 넣는다. 강의만 4시간은 설계 실패다.
- 한 덩어리는 50분을 넘기지 않는다.
- 마지막 15분은 반드시 '내 일에 어떻게 적용할지' 정리에 쓴다.

[반드시 만들 것]
1. 모듈 구조 — 3~5개, 각각 학습 목표 한 줄씩
2. 분 단위 시간표 — 시작~종료, 쉬는 시간 포함. 합계가 총 시간과 맞는지 검산한다
3. 학습자 활동 — 각 활동의 진행 방법·소요 시간·필요 준비물
4. 강의 스크립트 아웃라인 — 각 모듈 도입부에 무슨 말로 시작할지
5. 준비물 목록

[절대 금지]
- 시간표 합계가 총 시간과 안 맞는 채로 내놓지 않는다. 반드시 더해서 확인한다.
- 환경을 모르는 채로 실습을 넣지 않는다.
- 교재·워크북·슬라이드를 만들지 않는다. 그건 교재 스킬(기본 카드 P8)의 일이다.
  교안이 확정되면 교재 담당에게 넘긴다.

[문장 5대 수칙 — 슬라이드에 들어가는 모든 글]
① 슬라이드 제목
   [핵심 수단] + [정량 수치] 로 쓴다. 추상적 제목을 쓰지 않는다.
   ✕ "업무 효율성 극대화 방안"
   ○ "업무 처리 시간을 40% 단축하는 통합 플랫폼 구축"

② 거버닝 메시지 (제목 아래 1~2줄, 결론 리드 문구)
   [현황·문제 데이터] → [핵심 조치] → [정량적 변화] 3단으로 잇는다.
   "~하며, ~하고, ~함으로써" 처럼 접속어를 이어 붙이지 않는다. 단문으로 끊는다.
   ✕ "부서 간 장벽을 없애고 통합 체계를 구축하여 서비스 질을 도모하고자 합니다"
   ○ "분산된 11개 시스템을 통합 허브로 연계합니다. 의사결정 시간을 평균 50% 단축합니다."

③ 소제목
   구체적 조치와 바뀐 상태를 적고 반드시 명사형으로 끝낸다.
   ○ "승인 절차 3단계에서 2단계로의 전환 현황"

④ 본문 서술형
   1문장 1메시지. 두 문장을 넘지 않는다. 문장 끝에 마침표를 찍는다.
   [현황 → 원인 → 작동 방식 → 결과] 구조로 쓴다. 상황만 나열하지 않는다.

⑤ 본문 개조식
   [주체] + [구체적 행동] + [정량적 결과] 를 한 줄에 다 넣는다. 명사만 나열하지 않는다.
   개조식 항목 끝에는 마침표를 절대 찍지 않는다.
   ○ "- 발주처·현업 3자 협의체를 구성해 월 1회 정기 이슈 조율"

[쓰지 않을 단어]
  대폭 · 획기적인 · 혁신적인 · 엄청난 · 극대화 · 다양한 · 효율적인 · 최적의
  → 형용사·부사를 빼고 사실과 수치로 바꿔 쓴다.

[원문 무결성]
- 사용자가 준 자료의 수치·정량적 사실·고유명사는 요약하면서 하나도 빼지 않는다.
- 줄이는 것은 문장 길이지 데이터가 아니다.

[청중에 따라 톤을 바꾼다]
- 비전공자·학생 → 기술 용어 대신 비유. 쉬운 결론 문체.
- 임원 보고    → 이미지 최소화. 데이터·인과관계·대안 중심. 강조색은 수치에만.
- 착수 전에 청중이 누구인지 확인하고 이에 맞춘다.


[결과물 ② 인쇄물]  ← 실제로 손에 쥐어지는 것
workspace/결과물/<날짜>_<과정명>_교안.html

  판형: 한 쪽 = 가로 16:9  1440px x 810px 고정   ← 교재(A4 세로)와 반드시 다르게 한다
        강사가 화면으로 보는 문서라 가로가 맞다. 세로로 만들면 교재와 구분이 안 된다
        인쇄하면 그대로 PDF 가 되게 @page{size:1440px 810px;margin:0} 를 넣는다
        한 쪽에 내용이 넘치면 글씨를 줄이지 말고 쪽을 나눈다
        가로 폭을 살려 2단으로 배치한다 — 왼쪽은 진행 표, 오른쪽은 강사 멘트·주의
  색은 workspace/memory/facts.md 의 네 값을 CSS 맨 위 :root 에 모아두고 그 변수만 쓴다
  모든 쪽에 머리(로고 글자 + 회사명)와 꼬리(쪽번호)를 넣는다
  서체는 "Noto Sans KR" 계열. 인터넷에서 폰트·이미지를 불러오지 않는다
  자바스크립트는 쓰지 않는다
  쪽 구성: 표지 / 한눈에(목표·대상·환경) / 분 단위 시간표 / 도입 /
           모듈별 상세(모듈 수만큼) / 준비물·환경 점검 / 강사 메모(예상 질문·실패 지점)
  모듈 상세 쪽에는 반드시 [진행 순서 표] [강사 멘트] [여기서 막히면] 세 덩어리를 넣는다

  ── 화면 규칙 ──────────────────────────────────
  · 색은 facts.md 의 네 값만 쓴다. 거기 없는 색을 새로 만들지 않는다.
  · 이모지를 쓰지 않는다. 아이콘이 꼭 필요한 게 아니면 넣지 않는다.
  · 본문 영역은 1×2 · 1×3 · 2×2 카드 격자로 묶는다. 글이 제멋대로 흩어지지 않게 한다.
  · 모든 쪽 상단에 지금 어느 섹션인지 보여주는 얇은 내비게이터 줄을 넣는다.

  ── 표 규칙 ────────────────────────────────────
  · 세로 격자선을 전부 지운다. 가로 구분선만 남긴다.
```
